# Security model

This is a synthetic local engineering laboratory. No customer data, production
credentials, external paid model, SMTP server, real payment or arbitrary outbound
HTTP endpoint is required. Email writes a synthetic inbox; quota adjusts integer
units; HTTP is constrained to `/synthetic/<slug>` resources in the provider database.
Search reads a fixed synthetic catalog. These names describe lab tool semantics.

Tenant tokens are generated by the API and stored as hashes. Every resource lookup
is scoped by tenant; composite foreign keys reject cross-tenant references. This
lab does not supply production identity management, TLS termination, rate limiting,
row-level security, credential rotation or a hardened hosting environment.

Published AgentVersions are immutable. Tool selection is pinned in a validated plan
and checked against the version allowlist before intent creation. Retrieved documents
are untrusted data. Uploads enforce UTF-8/body limits. The deterministic model cannot
expand tool authority or override the persisted plan.

The API and recovery processes receive SELECT-only provider credentials. Recovery
has no mutating port. The dispatcher has a separate write capability. Compose exposes
only the API and console on loopback; PostgreSQL is loopback-bound for verification.
The provider/control services are private to the Compose network. Lab controls are
explicitly opt-in and operate only on synthetic, scoped tasks. A network user with
access to this lab is trusted to create synthetic tenants; it is not an Internet service.

An intent's identity, tool and payload fingerprint become immutable before dispatch.
A SENT or UNKNOWN intent prevents replay. Confirmation requires a matching external
observation and writes a terminal receipt atomically. A timeout is not proof of
failure; inconclusive observations remain unknown or move to manual review.

Structured logs emit committed identifiers and event names, never raw prompts,
documents, tool payloads, review notes or tokens. Events remain tenant-scoped in the
API. Verification scans authored source and documentation for credential/PII patterns;
this is a bounded pattern check, not a claim that all possible secrets are detectable.
